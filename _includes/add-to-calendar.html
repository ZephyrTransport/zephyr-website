{% comment %} Renders "Add to Google Calendar" + "Download .ics" links. Events render as all-day entries by default -- front matter only carries a free-text `time` string (e.g. "2 PM Eastern (1 PM Central...)"), not a structured/timezone-aware start time, so there's no reliable way to build a precise timed calendar slot from it alone. The human-readable time still shows in the calendar entry's description either way. Passing start_time + duration_minutes + timezone (all three) switches to a real timed VEVENT instead, using an IANA timezone so recurring events stay correct across Daylight Saving changes. Params: include.title include.date YYYY-MM-DD (or a Date/Time value), first/only occurrence include.time optional free-text time, shown in the description include.place optional location text (may contain HTML -- stripped) include.url page url (relative_url'd already or not, either works) include.rrule optional recurrence rule value, no "RRULE:" prefix e.g. "FREQ=WEEKLY;INTERVAL=2" include.until optional YYYY-MM-DD the recurrence stops after include.start_time optional 24-hour local time, "HH:MM" (e.g. "14:00") include.duration_minutes optional integer meeting length in minutes include.timezone optional IANA zone, e.g. "America/New_York" -- see _config.yml for the list of supported zones (must match a case below). start_time, duration_minutes, and timezone must all be given
